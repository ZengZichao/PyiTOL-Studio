# PyiTOL Studio 用户手册

**PyiTOL Studio** —— iTOL 注释桌面工作台。以 [pyitol](../../PyiTOL-项目代码/) 为唯一业务引擎的 macOS 桌面图形界面（PySide6），提供 iTOL 注释模板的可视化生成、模板反推（learner 回填）、pyiTOL 配置文件编辑，以及 iTOL 批量上传与导出。

- 英文版手册：[UserGuide.md](UserGuide.md)
- 适用版本：PyiTOL Studio 0.3.x（引擎 pyitol ≥ 1.0.3）
- 更新日期：2026-09-12

> **0.3.0 界面改版提示**：本版本按 *Instrument Dark* 设计系统（深色默认、浅色一等）重做了全部界面。
> 左栏改为「树卡片 + 注释单元列表（可拖拽排序）」，中栏数据区改为结构化数据网格（行号列 / 状态芯片 / 出错行标红），
> 右栏参数检查器支持搜索、分组折叠与字段级还原，页脚常驻校验横幅与「生成模板」按钮。
> 新增 `⌘K` 命令面板、`⌘N/⌘O/⌘S/⌘⇧E` 快捷键，欢迎页改为三张动作卡 + 最近工程（含路径与单元数）。

## 1. 简介与功能总览

PyiTOL Studio 把 [pyitol](../../PyiTOL-项目代码/) 命令行引擎的完整 iTOL 注释工作流搬进图形界面：

| 功能 | 说明 | 对应引擎能力 |
|---|---|---|
| 模板向导 | 选择类型 → 粘贴数据 → 填参数 → 预览 → 导出 `.txt` | `create_schema` + `TemplateGenerator`（31 种类型） |
| 主工作台 | 数据表格 + 参数检查器 + 实时模板预览（语法高亮） | 同上 |
| 模板反推 | 把已有 iTOL 模板 `.txt` 解析回可编辑单元（类型/分隔符/参数/数据全部回填表单） | `learn_template` |
| 配置文件生成器 | 可视化编辑 pyitol YAML 配置，字段与引擎 `config.example.yaml` 一一对应 | `--config` |
| 上传与导出 | Newick 树 + 模板批量上传 iTOL，按 8 种格式导出 | `ITOLAPIClient` |
| 工程文件 | `.pyitolproj`（JSON）保存全部注释单元，支持会话恢复与版本检查 | — |

界面遵循 macOS 视觉规范，深浅色自动跟随系统外观。所有工具栏按钮和对话框使用 Lucide 矢量图标。软件支持中文/英文实时切换（工具栏地球图标），语言偏好自动保存。

## 2. 安装与启动

PyiTOL Studio 提供两种安装形态：**打包版 .app**（推荐，无需配置 Python 环境）与 **pip 源码安装**。

### 2.1 环境要求

- macOS 12+（Apple Silicon / Intel）
- Python ≥ 3.10（推荐 3.11；仅 pip 源码安装需要）
- pyitol 引擎 ≥ 1.0.3
- PySide6 ≥ 6.5、pandas ≥ 2.0、PyYAML ≥ 6.0

### 2.2 方式一：打包版 .app（推荐）

把 `PyiTOL Studio.app` 拖入「应用程序」文件夹，双击启动。Python、PySide6、pyitol 引擎均已内置于应用内，无需另装环境。

- 首次启动若被 Gatekeeper 拦截（未公证的构建），右键点按 App →「打开」，或执行 `xattr -cr "/Applications/PyiTOL Studio.app"` 后再打开。
- 自行打包：`pyinstaller packaging/pyitolstudio.spec`，产物在 `dist/PyiTOL Studio.app`（详见 `packaging/README.md`）。

### 2.3 方式二：pip 源码安装

```bash
# 1) 准备环境（可用 micromamba/conda，或复用已装好 pyitol 的环境）
micromamba create -n python-3.11 python=3.11 -y
micromamba activate python-3.11

# 2) 安装引擎 pyitol（两种方式任选）
pip install pyitol                    # PyPI
# 或源码安装：
pip install -e /path/to/PyiTOL-项目代码

# 3) 安装 PyiTOL Studio
pip install "PySide6>=6.5" pandas pyyaml
pip install -e /path/to/PyiTOL-studio-项目代码

# 4) 启动
pyitol-studio          # 或等价的 python -m pyitolstudio
```

### 2.4 验证安装（可选）

```bash
# 核心逻辑测试（无需 Qt 显示器；Qt 用例无显示器时自动跳过）
cd /path/to/PyiTOL-studio-项目代码
pytest
```

## 3. 界面总览

启动后首先进入**欢迎页**；打开/新建工程后进入**三栏主工作台**。

```
┌──────────┬──────────────────────────────┬──────────────┐
│ 工程导航  │  数据表格（QTableView）        │  参数检查器    │
│ · 树文件  │  （支持从 Excel/TSV 粘贴）     │  （按类型自动  │
│ · 注释单元│──────────────────────────────│   生成的表单） │
│   列表    │  模板文本预览（语法高亮）       │              │
└──────────┴──────────────────────────────┴──────────────┘
顶部工具栏：新建 | 打开工程 | 保存工程 | 模板向导 | 导入模板 | 生成预览 | 导出当前模板 | 上传 iTOL | 配置文件 | 语言切换（地球图标）
```

- **语言切换**：点击工具栏末尾的地球图标，选择「中文」或「English」即可实时切换界面语言，无需重启；偏好自动保存，下次启动恢复上次选择。

- **左栏 · 工程导航**：当前树文件与全部注释单元；右键单元可删除。
- **中栏**：上方为数据表格（与所选单元双向同步：选中单元即载入其数据行，编辑单元格后自动回写单元并刷新预览；首列未匹配 ID 与缺失值以红色标出），下方为模板文本预览（类型头、SEPARATOR 行、注释、参数键、十六进制色值分别高亮，色值以自身颜色显示）。
- **右栏 · 参数检查器**：展示当前选中单元的参数表单；控件类型由声明式 IDL 决定（文本/整数/浮点/颜色/复选/下拉/列表），任何改动即时刷新预览。
- 悬停任一参数标签可查看官方说明提示。

## 4. 新建与打开工程

- **新建工程**：工具栏「新建」或欢迎页「新建工程」。工程初始未选择树文件。
- **打开工程**：工具栏「打开工程」，选择 `.pyitolproj` 文件；或从欢迎页「最近工程」列表**双击**打开；或把 `.pyitolproj` 文件拖入窗口。
- 打开或新建工程会自动清空上一个工程的单元选择，避免把编辑写入错误对象。
- 工程文件版本高于当前软件时，会明确提示「工程文件版本过新，请升级 PyiTOL Studio」。

> 树文件不必急于指定：点击「上传 iTOL」时若未设置树文件，会引导选择。

## 5. 模板向导（推荐入门路径）

工具栏「模板向导」打开四步向导：

### 第 1 步 · 选择类型

- 类型按 iTOL 官方分组排列：**Datasets（数据集）/ Tree structure（树结构）/ Metadata（元数据）/ Advanced（扩展）**，P0 高频类型（COLORSTRIP、SIMPLEBAR、MULTIBAR、HEATMAP、BINARY、TREE_COLORS、LABELS）排在最前。
- 共列出引擎注册的 31 种类型中支持向导的 29 种（`DATASET_MANUAL`、`DATASET_TREESTYLE` 为交互式/树样式类型，不提供向导表单）。

### 第 2 步 · 导入数据

- 直接把表格文本粘贴进文本框，或点「导入 CSV/TSV…」读文件。
- **分隔符下拉框**可选 `TAB / SPACE / COMMA`，粘贴与导入都按所选分隔符解析；占位提示会随分隔符变化。
- 列结构由所选类型决定（如 COLORSTRIP 为 `树 ID | 色带标签 | 颜色 #hex`；MULTIBAR/HEATMAP 等动态列类型自动命名 `value_1, value_2…`）。
- 「粘贴示例」按当前类型的列结构生成 3 行示例数据（颜色列填 #hex、标签/文本列填文字、形状列填形状名、数值列填数字，动态列自动补齐），可直接生成预览。

### 第 3 步 · 参数表单

- 表单按类型自动生成：数据集标签、颜色、宽度/边距等；悬停查看官方说明。
- 下拉（choice）、复选（bool）、颜色（#hex + 取色器）等控件取值会如实写进模板。

### 第 4 步 · 预览与导出

- 实时预览 iTOL v7 模板文本。
- 「导出模板…」保存为 `.txt`。生成的文件遵守官方规则：**SEPARATOR 行恒写作 `SEPARATOR <名称>`（名称后单个空格）**，与数据区实际使用的分隔符无关。
- 若数据值包含当前分隔符字符（如 COMMA 模式下值内含半角逗号），生成会**明确报错到行号与字段**并拒绝写坏列结构；SPACE 模式下因 iTOL 容忍自由文本中的空格而不做限制。

导出成功后向导关闭，主窗口状态栏显示「向导完成：模板已导出」。要把模板加入当前工程继续编辑，可再用「导入模板」把导出的 `.txt` 反推回单元。

## 6. 主工作台：数据表格 · 参数检查器 · 实时预览

1. 在左栏点击某个注释单元 → 右栏出现其参数表单，中栏表格载入该单元的数据行，下方立即生成预览。
2. **数据表格与单元双向同步**：双击单元格编辑后，改动自动回写到所选单元并刷新预览。表格支持快捷键 ⌘V（或右键「粘贴剪贴板数据」）直接粘贴 Excel/TSV 数据（自动识别 TAB / 逗号 / 空格分隔）。打开或设置树文件后，软件自动在后台读取参考树的全部叶 ID，首列中未出现在树里的 ID 与空缺值会以红色背景标出。
3. **参数检查器**：任意改动（文本回车/失焦、复选、下拉、颜色）即时重生成预览，无需手动刷新。
4. 「生成预览」按钮可随时强制刷新；「导出当前模板」把所选单元（含表格改动）写为 `.txt` 模板文件。
5. 参数表单底部如出现「— 其他参数（learner 发现）—」区，说明导入的模板含有软件参数目录之外的参数，可在此直接编辑，它们同样会写回导出模板。

## 7. 模板反推（导入已有 iTOL 模板）

工具栏「导入模板」（或直接把 `.txt` 拖入窗口）选择 iTOL 模板文件：

- 软件调用引擎 learner 解析每个数据集块，识别**类型、头标识、分隔符、标签、颜色、全部参数、图例（LEGEND_*）与数据行**，逐个生成注释单元并加入当前工程。
- 之后在左栏选中该单元，即可看到回填后的表单；修改参数或数据后可再次导出，或直接进入「上传 iTOL」。
- 往返一致性（learn → generate → learn）由自动化测试在 45 个官方 iTOL v7 样例中的 9 个代表类型上回归验证（类型/表头/分隔符/参数集/行数完全一致）。
- 若文件中没有可识别的数据集，状态栏提示「未在文件中找到可识别的模板数据集」。
- 若模板类型引擎未注册（极少数自定义类型），选中单元时会提示「未知模板类型」，不影响其他单元。

## 8. 工程管理：保存 · 最近工程 · 删除单元

- **保存工程**：工具栏「保存工程」→ 选择 `.pyitolproj` 路径（自动补扩展名）。保存采用原子写（先写临时文件再替换），避免半写文件。
- **最近工程**：欢迎页展示最近 8 个工程（仅显示仍存在的路径），双击打开。
- **删除注释单元**：在左栏右键单元 →「删除注释单元」。删除后立即从工程与导航中移除；若该单元正被选中，检查器与预览同步复位。

## 9. pyitol 配置文件生成器

工具栏「配置文件」打开可视化编辑器，字段与引擎 `config.example.yaml` 一一对应（由测试强制对齐）：

| 字段 | 说明 | 默认 |
|---|---|---|
| `api_key_file` | iTOL API 密钥文件路径（纯文本 Key） | `.itolapi.key` |
| `default_format` | 默认导出格式 svg/png/pdf/tiff/eps/newick/nexus/phyloxml | `svg` |
| `output_directory` | 导出输出目录 | `.` |
| `template_directory` / `tree_directory` | 模板/树文件目录（留空用当前目录） | 空 |
| `log_level` | DEBUG…CRITICAL | `INFO` |
| `log_file` | 日志文件（留空仅控制台） | 空 |
| `multi_tree_mode` | 多树策略 ask/first/last/random/split/all | `ask` |
| `name_format` | 分类学命名格式 auto/gtdb/embedded/ncbi/underscore/mixed | `auto` |
| `taxonomy_delimiter_mode` | 嵌入式命名解析 segment/reverse/greedy | `segment` |

- 「导出 YAML…」保存文件；导出路径经规范化处理并拒绝包含 `..` 的穿越路径（用户在系统保存对话框中确认的任意可写位置均可，包括外置磁盘）。
- 生成时对含 YAML 特殊字符（冒号、井号、引号等）的值自动加双引号，空字符串显式写作 `""`（而不是 null），保证 `pyitol --config <文件>` 可直接解析。
- 取值非法（如下拉被手动改动为不存在的选项）会在导出前列出全部错误。
- 点击保存对话框的「取消」不会产生任何错误提示，静默返回；目标位置不可写时错误会显示在对话框内。

## 10. 上传 iTOL 并导出

### 10.1 前置条件

1. **iTOL 订阅账号**（iTOL 批量接口要求）。
2. **API Key**：在 iTOL 用户页面生成后，二选一提供：
   - 环境变量：`export ITOL_API_KEY=你的KEY`（推荐，启动 `pyitol-studio` 前设置）；
   - 本地密钥文件：内容仅为 Key 纯文本的文件，路径填入对话框「API 密钥文件」。
   - 软件界面**永不**显示或存储 Key 明文。
3. Newick 树文件（`.nwk/.newick/.tre/.tree/.txt`）。

### 10.2 操作流程

1. 工具栏「上传 iTOL」：
   - 若工程尚未设置树文件，先弹窗选择；
   - 若工程中已有注释单元，会先在后台把它们**自动导出为模板文件**（后台线程执行，状态栏显示进度），随后打开上传对话框并预填模板列表。
2. 上传对话框中可：
   - 修改树文件路径；
   - 「添加模板…」追加任意 `.txt` 模板、「移除所选」剔除；
   - 选择导出格式（8 种）；
   - 指定**导出目录**（默认为树文件所在目录）；
   - 勾选「覆盖 iTOL 上同名工程（force）」。
3. 点「上传并导出」：进度条转为忙碌态，引擎自动重试（429/500/502/503/504，指数退避）。
4. 完成后显示 `tree_id` 与导出文件路径；失败则显示引擎的错误消息（可重试）。
5. **上传进行中对话框不可关闭**，防止后台任务被中断；结束后可正常关闭。

> 注意：iTOL 批量接口没有幂等键，重试的上传可能在服务器产生重复树；上传后请到 iTOL 确认目标工程（引擎会在每次重试 POST 时记录警告日志）。

## 11. 拖放与快捷操作

把文件直接拖入主窗口：

| 拖入文件 | 行为 |
|---|---|
| `.pyitolproj` | 打开工程 |
| `.txt` | 模板反推导入（learner） |
| 其他（`.nwk`/`.newick` 等） | 设为当前工程的树文件，并自动加载叶 ID 用于数据校验 |

- 扩展名判断不区分大小写；不存在的路径会被忽略。
- 欢迎页双击「最近工程」条目即可打开对应工程。

## 12. .pyitolproj 工程文件格式

`.pyitolproj` 是带版本号的 JSON 文本（透明、可 diff、可进版本库）：

```json
{
  "pyitolproj_version": 1,
  "name": "未命名工程",
  "tree_path": "/path/to/tree.nwk",
  "units": [
    {
      "unit_id": "1a2b3c4d5e6f",
      "type_name": "dataset_colorstrip",
      "label": "phylum_strip",
      "color": "#dd4477",
      "separator": "TAB",
      "columns": ["id", "value", "color"],
      "data_rows": [{"id": "A", "value": "1", "color": "#ff0000"}],
      "parameters": {"STRIP_WIDTH": "25"},
      "legend": {},
      "source": "manual"
    }
  ]
}
```

- `DATASET_LABEL`/`COLOR` 存储在单元的 `label`/`color` 字段，不重复写入 `parameters`。
- 版本号高于当前软件时拒绝打开并提示升级；损坏的 JSON 或缺失 `units` 字段会给出明确错误。

## 13. 安全与隐私约定

- **API Key 只来自环境变量 `ITOL_API_KEY` 或密钥文件**；界面不提供明文输入框，也不持久化 Key。
- 所有经对话框产生的写路径规范化处理，并在规范化**之前**拒绝 `..` 穿越段（防止 `/a/../../etc` 被静默改写为合法路径）；不限制目标目录——用户在系统文件对话框中确认的位置均可写。
- 上传内容仅通过 HTTPS 发往 iTOL 官方批量接口。

## 14. 常见问题（FAQ）与故障排除

**Q1：预览里没有树图？**
v1 的预览策略是「文本模板预览 + 上传 iTOL 后远程渲染」；本地不渲染树形图。需要本地图形请上传后在 iTOL 导出 SVG/PDF。

**Q2：COMMA 分隔导出报错「含分隔符」？**
数据值里含半角逗号会破坏列结构。按提示清理该行该字段，或改用 TAB/SPACE 分隔。

**Q3：双击最近工程没反应/提示打开失败？**
工程文件可能已被移动或删除（欢迎页仅显示仍存在的路径）。若仍失败，状态栏会显示具体原因（如文件不是有效 JSON、版本过新等）。

**Q4：上传时提示「未找到 iTOL API Key」？**
设置环境变量 `ITOL_API_KEY` 后**重新启动** Studio，或在对话框中填写密钥文件路径。

**Q5：导入模板后某个类型没有表单？**
该类型可能未被当前版本引擎注册（显示「未知模板类型」）。请升级 pyitol 引擎。

**Q6：为什么向导里改了下拉选项但模板里没变？**
这是预览版期间的缺陷（下拉取值丢失），当前版本已修复——请升级到最新版；如仍复现请提交 issue。

**Q7：GUI 测试/无显示器环境如何运行？**
`QT_QPA_PLATFORM=offscreen pytest tests/test_app_qt.py`；无 Qt 环境时 Qt 用例自动跳过，核心逻辑测试不受影响。

**Q8：一次能上传多少模板？**
上传数量走 iTOL 批量接口（打包为单个 zip），无软件侧硬限制；请以 iTOL 服务端限制为准。

**Q9：打包版 .app 首次启动被拦截？**
未做公证的构建会被 Gatekeeper 拦截：右键点按 App →「打开」，或执行 `xattr -cr "/Applications/PyiTOL Studio.app"`。对外分发请按 `packaging/README.md` 完成 Developer ID 签名与公证。

**Q10：表格里有些 ID 标红了？**
已加载参考树时，首列中不出现在树里的叶 ID 会标红——通常是 ID 拼写不一致（如连字符/下划线差异）。若尚未加载树文件则不做校验。
